## Tables & Schema Definitions

### 1. `tickets`
- `ticket_id` (TEXT, PK): Unique ticket identification string (e.g. INC100001).
- `created_date` (TEXT): ISO timestamp when ticket was created.
- `resolved_date` (TEXT): Timestamp when ticket was marked resolved.
- `channel` (TEXT): Intake channel (Phone, Email, Chat, Portal).
- `category` (TEXT): Primary ITIL category (Hardware, Application, Access, Network, Server, Facilities).
- `short_description` (TEXT): User description text analyzed by ML vectorizer.
- `affected_asset` (TEXT): Hostname/Asset tag associated with ticket.
- `priority` (TEXT): P1-Critical, P2-High, P3-Medium, P4-Low.
- `is_workaround` (INTEGER): 1 if temporary workaround applied, 0 otherwise.
- `effort_hours` (REAL): Engineer time spent on ticket.
- `status` (TEXT): Open, Resolved, Closed.
- `true_cluster_id` (TEXT): Ground truth cluster label for ML accuracy evaluation.

### 2. `clusters`
- `cluster_id` (TEXT, PK): Cluster code (e.g. CL-APP-01).
- `cluster_name` (TEXT): Human-readable issue title generated by NLP.
- `ticket_count` (INTEGER): Number of tickets in cluster.
- `total_effort_hours` (REAL): Cumulative engineer hours.
- `recurrence_interval_days` (REAL): Mean days between consecutive incidents.
- `confidence_score` (REAL): Clustering similarity confidence %.
- `recommended_fix` (TEXT): Permanent Fix (Problem Management) solution recommendation.
- `priority_score` (REAL): Automated issue ranking score.
- `cost_saved_usd` (REAL): Projected ROI cost savings in USD.

### 3. `stakeholder_feedback`
- `id` (INTEGER, PK): Primary key ID.
- `manager_name` (TEXT): Service Manager reviewer name.
- `cluster_id` (TEXT, FK): Targeted recurring issue cluster.
- `issue_correct` (INTEGER): 1 if issue clustering was accurate, 0 otherwise.
- `approve_fix` (INTEGER): 1 if permanent fix approved for implementation.
- `satisfaction_rating` (INTEGER): Rating scale 1 to 5.
